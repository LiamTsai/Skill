# progress-bars

在 Claude Code 輸入框上方顯示進度條，一眼看到哪些在跑、哪些已完成。

```
專案 UI 重新設計                                                                ×
  ● Hades 風格 UI 改作      ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  72%  12m / ~5m   ×
  ✓ 調整色票                ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 100%  8m          ×
Fix upload                                                                      ×
  ● localStorage 上傳       ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  51%  3m / ~15m   ×
```

## 顯示方式

- **依 session 分組**：每個 session 一個標題列，底下是它的每個任務（每個需求一列）。
- **每個 session 看到的都一樣**：包含自己在內，所有 session 用同一份共用資料、同樣的規則畫，順序依各 session 第一個任務開始的時間排（還沒有任務的 session 排最後）。資料每 10 秒同步，所以最多差幾秒。
- **狀態**：● 執行中、✓ 完成、✗ 失敗或中斷；有在跑但還沒任何任務的 session 標題旁顯示「執行中」
- **進度條與百分比**：由 Claude 回報；沒有回報時顯示 `…`
- **時間**：執行中顯示「已用時間 / ~預估剩餘」（例如 `3m / ~25m`）。剛開始、還沒有根據時只顯示已用時間：同一個任務第二次回報起才顯示預估。完成後顯示總用時
- **同步失敗**：連續 3 次（約 30 秒）讀不到 session 清單或共用 store 時，最上面顯示一行黃色警告和錯誤原因，下一次同步成功就消失。偶爾一次讀到別的 session 寫到一半的 store 不算：那次沿用上次讀到的進度
- **×**：任務列的 × 隱藏那個任務，標題列的 × 隱藏整個 session。隱藏是所有 session 共用的（重開也一樣），等它回報更新的進度才會再出現。列不會自動消失

## 列從哪裡來

- **每個需求**：你送出的每個需求自動一列，回合開始時出現、結束時打勾。
- **Claude 的回報**：plugin 提供 `report_progress` 工具；系統提示裡有說明，每則需求也會附一段提醒，要 Claude 只要用到工具，第一步就用 `id: "current"` 回報百分比（不報預估時間），之後每一步更新，有了根據再加上預估時間。並行的工作（子 session、長時間建置）會用自己的 id 另開一列。
- **子代理**：用 Agent 工具開的子代理自動追蹤，結束時打勾。
- **其他 session**（Claude Code Desktop）：每 10 秒讀一次 App 的 session 清單；每個裝了這個 plugin 的 session 都把自己的任務寫進共用的 plugin store，所以所有 session 的進度互相看得到。正在跑、或回報過任務的 session 會列出來。
- **共用 store 的清理**：每天由一個 session 清一次，只清掉不可能再畫出來的資料：App 裡已封存或刪除的 session 的進度與 × 紀錄、任務已不在的 × 紀錄，以及舊版每次同步寫的狀態。還畫得出來的列不會被清掉。

## 點擊

- 點 session 標題：由目前這個 session 開出的 session 用 App 的切換工具直接切過去；其他 session App 不允許程式切換，改用它的 `claude://` 連結開啟，跟在 App 外點連結一樣。都失敗時才跳提示請你從側邊欄點開。

## 注意

- 百分比與預估時間是 Claude 自己估的，不是量測值。
- 系統提示會多一段說明，Claude 在多步驟工作時會多幾次工具呼叫。
- 子代理沒辦法點擊切換過去（plugin API 沒有這個功能）。
